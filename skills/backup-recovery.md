# 备份新鲜度与恢复演练

## 证据清单

确认备份对象、实际主机/注册 target、备份任务、数据范围、保存位置、加密与密钥
保管人、保留策略、恢复负责人、允许的数据丢失时间 RPO、恢复耗时 RTO。
记录 UTC 采样时间、最近成功的备份完成时间及数据截止时间、任务退出状态、
备份 ID/大小/完整性清单/验证结果、最后一次恢复演练时间、报告与事件引用。
状态备份与业务数据备份分开验收；ops-agent 文件快照不能替代数据库/卷备份。

以“当前时间 − 最后可恢复数据截止时间”与 RPO 比较；文件 mtime、目录里有文件、
任务 exit=0 或通知送达都不能单独证明备份新鲜可恢复。时间戳在未来、缺失或跨机
时钟差不明记 unknown；超过 RPO 记异常，校验失败记不可用并保留旧备份。

备份和状态目录可能含原始秘密、会话、SSH/通知配置及审批信息。不要通过 `read`
或 `cat` 把备份、快照原件、凭据、私钥送进模型。只读取专门设计的不含秘密的
摘要/manifest 字段；不确定时停止，由人本地核对并返回脱敏结果。

## 只读命令

以下为测试备份任务示例，替换为已确认的任务与目录。每条独立经 `bash` 守门；
远程只用注册 target。命令只辅助检查元数据，最终依据备份工具的验证与恢复结果。

```bash
date -u
ls -ld /srv/backups/app
ls -lh /srv/backups/app
systemctl status app-backup.service --no-pager
systemctl list-timers --all --no-pager
journalctl -u app-backup.service -n 100 --no-pager
df -h
```

日志也可能含秘密，限定范围并脱敏。备份软件的 list/check/verify 命令按实际工具
选定，不假设它们在 R0 白名单；先列完整命令、读写影响和限时，非 R0 经
`ops_approve` → `ops_exec` 工具内确认执行。某些 verify 会写缓存/锁，需如实说明。

## 变更与审批

1. **演练计划**：选明确备份 ID 与恢复时间点；准备隔离测试主机/目录/数据库、
   容量、网络隔离、测试密钥及检查清单，确认不会连接生产、启动真实调度或发送
   外部通知。写明预期内容/权限、业务探针、RPO/RTO、清理与失败退出计划。
2. **人工审批**：恢复、解压、复制、改权限、启动服务、清理演练数据均为变更。
   通过 `ops_approve` 请求具体命令确认，再 `ops_exec`；已有固定场景可用
   `scenario_run` 自带确认。`ask_user` 仅作澄清。拒绝/无确认通道即停止，禁止
   裸 `bash`、直接 tar/rsync/cp 或改白名单绕审批；解包前核对目标、绝对路径、
   路径穿越、符号链接与覆盖范围，不把任意归档直接解到运行目录。
3. **恢复与核实**：记录开始/完成时间、命令状态、execution_id 和证据引用；
   按备份工具的正式恢复方式写入隔离环境。内容校验、属主/组/权限、服务启动及
   业务只读后验分别记录，任何一步失败不能宣称通过。状态恢复不得重新启用旧
   审批、运行锁/心跳、待发通知或定时任务；先停调度，由人核对身份与安全状态。
4. **回退**：覆盖现有测试文件前保留可恢复副本/快照；`ops_rollback` 展示差异并
   再次请求人工确认后恢复文件。数据库或卷使用各自的恢复方案。回退后重跑内容、
   权限和业务后验；后续服务变更与清理仍需新审批。

## ops-agent 状态备份与隔离恢复

先停止 daemon、托管服务、交互 Agent 和其他状态写者，再由操作者确认已静止。
`--quiesced` 是操作者声明，不能代替停写。以下由人在离线的本地受保护终端执行；
Agent 的 `ops_exec` 会写入执行记录，破坏源状态停写前提，不能代执行备份或恢复。
路径换成新建、私有且离线保护的
目标，备份含未脱敏原件，不能上传或读进模型。

```text
opsx state backup /secure/opsagent-backup --quiesced
opsx state verify /secure/opsagent-backup
opsx state restore /secure/opsagent-backup --to /isolated/fresh-opsagent-state --quiesced
```

恢复目录必须全新且不存在，不能覆盖当前运行状态。核实恢复后隔离旧审批、禁用
排期并暂停 active 长目标，保留已用轮次；running 执行转为 unknown、运行记录转为 interrupted；核实未发送旧通知，
再逐一人工重新授权需要启用的任务。先在隔离环境只读 doctor/检查，原状态留作
回退，不能因 verify 通过就宣布恢复完成。

## 停止条件

无可用备份、校验不一致、密钥不可用、目标/恢复时间点不明确、无隔离/空间不足、
需覆盖生产、权限不能恢复或备份包含不受信任路径时停止。恢复中出现
running/unknown、超时断线，先用 `ops_executions` 查询并只读核实，由人处理
`opsx executions resolve`；不自动重放恢复、解压、回滚或删除旧备份。

## 可重复验收

用固定测试数据集与明确备份 ID，在新建的隔离环境完成恢复；比较文件/业务记录
计数、校验值、关键数据截止时间、属主/组/权限及只读业务查询，确认实际 RPO/RTO
在预设阈值内。再次在另一个空的隔离目录恢复同一备份，要求相同验收结果；拒绝
审批必须无恢复写入，故意损坏的测试备份必须校验失败且不覆盖现有文件。保留
两次演练的目标、时间戳、备份 ID、execution_id、差异、后验和失败记录。缺少
真实恢复证据记 unverified；无法验证新鲜度记 unknown，不能用本地桩测试代替。
