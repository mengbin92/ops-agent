# 个人运维 Agent：现状、缺口与排期

评估日期：2026-10-21。依据当前仓库实现、README、设计与复审记录；本次运行 `./opsx selftest`，结果 **111/111 passed**（W1/W2 交付后为 143/143，见第 4 节状态列）。未连接真实 LLM、SSH、K8s 或通知服务。

## 1. 结论与目标

项目已经具备个人运维 Agent 的执行底座：独立对话、工具调用、SSH、审批、快照、审计、技能、只读子代理、定时任务、会话和长期记忆。下一阶段的主要工作是补齐日常运维闭环：

> 明确管理对象 → 确定性检查 → 发现异常 → 主动提醒 → 保留事件与证据 → 人工批准变更 → 验证恢复。

当前适合有人在场的排查与受控操作；长期无人值守的主要缺口是结果可信度、通知、失败可见性和恢复能力。这个判断是产品就绪度评估，不是对所有命令安全性的证明。

建议交付两个版本：**第 4 周交付只读巡检试用版，第 5 周验收连续运行，第 8 周交付完成恢复演练的受控变更版**。另留 1 周机动时间。

## 6. 发布验收与近期不做的内容

只读版必须验证：异常没有被“正常”汇总覆盖，unknown 不当作 healthy；调度中断和通知失败可见；异常与恢复各有可定位的证据；7 天测试环境试运行中没有未解释的漏跑。单机通知无法在宿主彻底宕机时发送消息；需要这类保障时，将心跳超时检查放在另一台已有主机或外部服务。

受控变更版必须验证：审批绑定正确对象；写操作不被盲目重放；命令与业务健康分别判定；回滚经确认且能恢复测试环境。文件快照只能恢复文件或展示捕获状态，不能替代数据库备份、卷快照、部署回退和业务级恢复方案。

近期延后：Web UI、移动端/双向 IM、多用户 RBAC、多租户、云厂商全覆盖、向量数据库/知识图谱、复杂 DAG、跨主机事务、无审批自动自愈、完整 shell AST。外部告警接入、HTTP/TLS 探针、记忆更新/删除排在主闭环之后，按实际使用频次进入下一期。

当前测试说明的是本地回归基础较完整，不代表已验证真实生产环境，也不构成对恶意 Agent 的强隔离。现有线性命令分类、远程未知状态、秘密识别漏报等边界，应以收窄操作范围和测试主机演练控制。
