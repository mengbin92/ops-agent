## 2. 工作包与执行顺序

以下优先级表示交付顺序；“高”表示正式发布阻塞，不表示已发现线上事故或新的安全漏洞。
环境接入后立即开始只读观察，恢复演练与发布门禁开发可并行进行；影响运行行为的重大修复后重新计时。

| 顺序 | 状态 / 优先级 / 严重度 | 工作包 | 完成标准 |
| --- | --- | --- | --- |
| S1 | ⚠️ 待执行 / P1 / 高 | 专用测试环境、验收基线和留存准备 | 固定候选版本、独立状态目录、测试 target/服务、允许目录、通知接收范围；明确凭据和原始证据的私有保存位置 |
| S2 | ⚠️ 待执行 / P1 / 高 | 真实只读巡检、模型和通知验收，启动连续观察 | 真实调用与通知送达有证据；LLM 不可用仍上报规则异常；按实际开始时间连续计满 7 天，无未解释漏跑 |
| S3 | ⚠️ 待执行 / P1 / 高 | 实机受控变更、SSH 断线和离线恢复 | 拒绝、授权、快照、后验、unknown 防重放及恢复均有实际证据，文件和服务恢复可复核 |
| S4 | ⚠️ 待执行 / P1 / 高 | 正式发布门禁与验收问题修复 | 正式 tag 缺证据、证据未通过或验证对象不匹配时拒绝发布；候选版仍能带明确未完成状态发布 |
| S5 | ⚠️ 待执行 / P1 / 高 | 正式版收口 | S2/S3 的全部门禁、7 天记录及 S4 检查通过；同步版本文档并按既有流程发布、回读制品结果 |

### S1：先固定测试范围和证据留存

2026-10-26 进展：已按用户选择接入 `localServer`，并将调度迁到该 Linux 主机的用户级 systemd；
规则巡检 15/15 正常，真实模型调用、单实例及自动拉起通过。通知、归档和完整观察仍待验收，
见[试运行准备记录](../validation/2026-10-26-readonly-trial.md)。下列整项尚未全部完成。

- [ ] 按[实机环境要求](../ops/w8-real-environment.md)确认专用 SSH target、可中断服务、允许目录、测试 LLM 和专用通知渠道；不能默认使用生产目标。
- [ ] 固定源码 commit、工作树差异、代码/策略摘要和运行平台；为测试设置独立 `OPSX_STATE_DIR`，不复用实际审批、排期和通知配置。
- [ ] 确定巡检频率、预算、systemd 或 launchd 托管方式；复用 [docs/ops](../ops/) 的既有示例，不另建调度系统。
- [ ] 按频率核算证据留存：运行记录保留 200 份、报告 100 份、会话 300 份；每 5 分钟执行时，每次一份报告也只能保留约 8 小时 20 分钟。先选择足够低的频率，或在轮转前将证据复制到私有归档；验收首日记录必须能留到末日复核。
- [ ] 确认远程写入和外发测试通知的授权范围后再执行对应步骤。仓库文档只记录目标别名、脱敏摘要和证据索引，不写真实 IP、域名、上游供应商名称或任何凭据；完整备份与原始输出保存在私有目录。

验收：环境清单、版本基线和留存办法可复核；尚未提供的项目保持待执行，不推断为已配置或不可用。

### S2：只读闭环与真实 7 天观察

- [ ] 按[实机步骤](../ops/w8-real-environment.md)验证实际模型响应、SSH 只读输出和确定性巡检；保留退出码、采样时间、目标别名、脱敏输出与 run/session/report 索引。
- [ ] 验证首次异常、持续异常去重、升级、恢复、通知失败和补发；以接收端实际收到为准。模型鉴权失败、临时不可用或预算耗尽时，规则异常仍应进入报告和通知。
- [ ] 启动只读托管，记录北京时间的实际开始时间、版本、巡检频率和预期次数；观察期间冻结测试目标配置，避免同一报告跨探针指向不同端点。
- [ ] 每天回填既有[7 天记录表](../releases/2026-10-22-readonly-trial.md)，核对排期、成功/失败、中断/错过、通知和误报漏报；每个异常都能定位实际证据。
- [ ] 覆盖调度重启、LLM 不可用、通知失败和恢复。若需要宿主宕机后及时告警，复用另一台已有主机的监控；本机调度恢复时的心跳检查不能替代外部存活检测。

验收：真实连续 7 天，无未解释漏跑；巡检异常/恢复通知能追溯到对应 run、session 和完整报告。
心跳、初始化失败或超时等缺少完整巡检产物的通知，应能追溯到对应事件、错误及实际存在的运行记录，并明确缺失原因。
交付日期、本地桩和加速循环均不能抵扣观察时间；探针、通知状态机、调度推进或执行记录重大修复后重计 7 天。

### S3：测试主机上的受控变更和恢复

- [ ] 执行[实机清单第 4–8 步](../ops/w8-real-environment.md)：无审批拒绝且文件不变；批准后仅执行对应目标和完整命令；保留快照、execution_id 及前后内容/权限证据。
- [ ] 验证“命令 exit=0 但服务不健康”仍判 `verify_failed`，并在确认回滚后独立验证实际服务响应；不能仅恢复文件就认定业务恢复。
- [ ] 在允许范围内制造 SSH 超时/断线，确认进入 `unknown` 并拒绝重放；人工核实实际结果后再 resolve，不以清理状态代替核实。
- [ ] 按[状态恢复流程](../ops/state-backup-recovery.md)停止全部写入者，创建带时间戳的私有备份、校验，再恢复到全新目录；核对原始快照、文件权限、审批隔离、排期/通知停用及运行状态转换。
- [ ] 将日期、执行人、版本、逐项结果和脱敏证据索引归档到 `docs/validation/`；失败、不适用和未执行分别注明原因，必需门禁不因标记 `N/A` 自动通过。

验收：实机清单中的真实模型、SSH 恢复、断线未知结果、服务后验、通知均有通过证据；
目标/目录不符、快照不完整、结果未知或影响超出测试范围时停止写入并核实。

### S4：将正式发布要求落实到代码

- [ ] 定义一份最小的脱敏验收清单，保存待发版本、已观察候选基线、代码/策略摘要、逐项外部验收结果、连续观察起止时间、证据索引和人工复核结论；原始敏感证据不入库。
- [ ] 在 [Release workflow](../../.github/workflows/release.yml)发布正式 tag 前校验上述清单：缺失、未通过、观察不足 7 天或代码/策略变化时阻断 publish；仅修改发布文档不应使验证对象失配。候选 tag 允许外部未通过，但必须维持候选标记。
- [ ] 复用标准库和既有脚本模式实现最小校验；为候选版允许未完成、正式版拒绝缺失/失败/过期证据、正式版接受完整证据添加有效回归，并同步[发版流程](../ops/releasing.md)。
- [ ] 根据 S2/S3 实际发现的问题逐项修复，每项检查共享实现、所有调用入口、测试及旧状态兼容；按工作包提交，不把无关功能混入候选版收口。

注意：[本地演练脚本](../../scripts/w8_acceptance.py)的 `external_gates()` 固定生成 `blocked`，
当前也没有导入实机证据的参数。不能只在 CI 加 `--require-external`，也不能修改本地桩报告伪造通过；
真实验收清单需要独立校验，并与实际验证过的实现绑定。

验证范围：`.github/workflows/release.yml`、`scripts/` 中最小校验入口、对应 `tests/`、
`docs/validation/` 和 `docs/ops/releasing.md`；若改动运行逻辑，同时覆盖 CLI/Agent/MCP/RPC 的相关入口。

- [ ] 同步 `VERSION`、`CHANGELOG.md`、README 和 `docs/releases/release-<tag>.md`；遵循[既有发版流程](../ops/releasing.md)的 `develop → main → tag → Release`，发布后核对精确 tag、源码包、权限和校验和。

## 3. 正式版之后的候选工作

| 状态 / 优先级 / 严重度 | 候选项 | 启动条件与最小范围 |
| --- | --- | --- |
| ⚠️ 未排期 / P2 / 中 | HTTP/TLS 确定性检查 | 试运行证明现有资源/服务探针不足，且没有既有监控可复用；先覆盖实际所需的一个服务健康地址和证书到期，沿用现有状态、报告和通知链路 |
| ⚠️ 未排期 / P2 / 中 | 同次巡检固定目标端点 | 当前已知每个远程探针可能重读目标配置；试运行先冻结配置。确需运行中改 targets 时，参考既有变更流程固定端点，并测试中途改向后仍使用原端点或明确标为不完整 |
| ⚠️ 未排期 / P2 / 低 | 记忆更新/删除和证据保留改进 | 有实际误记忆或轮转丢证据案例后再做；沿用文件状态，不引入数据库、向量库或通用归档平台 |

近期不排期 Web UI、双向 IM、多租户/RBAC、复杂 DAG、跨主机事务和无审批自动自愈。
2026-10-25 创建规划时仅新建本地分支并保存文档，未实施、部署或连接真实上游。
后续实际进展按 S1/S2 的记录更新；正式发布仍须通过全部外部验收。
