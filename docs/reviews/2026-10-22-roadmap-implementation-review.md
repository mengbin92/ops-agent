## 1. 安全边界

| 级别 | 可复现问题与影响 | 修复位置及结果 |
| --- | --- | --- |
| P1 | 自定义 `OPSX_STATE_DIR` 的 `notify.json`、快照原件没有默认目录的读取保护；符号链接到敏感目录文件也可绕过 `read` | `core.sensitive_path/sensitive_dir` 按真实状态目录校验；`tools._read` 同时检查解析后的敏感目录 |
| P1 | `cat<.env`、`cat <.env` 的输入重定向未被当作文件参数检查 | `core.sensitive_command` 使用标准库 `shlex` 分出重定向标点，共用入口拒绝 |
| P1 | `kubectl get secret -oyaml/-ojson`、`kubectl config view --raw` 可输出凭据 | 共享敏感命令检查覆盖紧凑输出参数和原始 kubeconfig 导出 |
| P1 | 空 context、变量 context、重复冲突的 context 可获审批；复合命令可能展示前一只读段的 context；`auth reconcile` 被当作只读而免 context | 发戳和验戳共用固定 context/namespace 校验；展示写操作段的实际最终参数；`auth` 仅 `can-i/whoami` 享受只读豁免 |
| P1 | 回滚预览先生成 diff 或截断，再脱敏，丢掉 PEM 首尾标记后会留下私钥片段 | `core._diff_text/rollback_plan` 先脱敏再比较、截断；原文不同而脱敏文本相同时明确提示有变化；原始快照不改动 |
| P1 | 快照执行期间审批过期、被撤销或目标改变，快照后仍继续变更 | 本地与 SSH `exec_change` 在快照完成后重新验戳，失败中止并保留快照 id |
| P1 | 调度 prompt 在截断前未脱敏；调度 JSON 权限不固定；RPC、单发和远程快照错误可回显凭据 | 调度注册、持久化和摘要先脱敏，注册表按 0600 替换；相关异常出口统一脱敏 |

已检查 `core` 的 CLI、MCP、Agent 调用方和远程通道；共享层修复同时覆盖这些入口，未复制另一套安全规则。

## 2. 巡检与运行状态

| 级别 | 可复现问题与影响 | 修复位置及结果 |
| --- | --- | --- |
| P1 | 规则已有 critical/unknown，模型回复“结论：正常”仍可让运行记录和 `--once` 返回正常 | `schedule._finish_run` 合并结构化规则结论，模型只能补充风险，不能降低规则严重度或抹掉不完整 |
| P1 | 预设检查无法执行、摘要写入失败，模型仍可宣称正常 | `_run_preset_checks/_execute_run` 保留明确错误并记录 failed；重试摘要合并写入失败也结束为 failed，避免遗留 running |
| P1 | 同会话第二次 `inspect` 覆盖此前不同目标/分组的异常；模型失败重试换会话后也会丢首轮证据 | `checks._merge_signal` 按实际采样目标、分组更新；调度复用它合并尝试结果，保存全部关联报告路径 |
| P1 | 同一目标既有 critical 又有 unknown 时，目标结论是“异常”，通知却据此认定采集完整并清除旧告警 | 信号保存每目标完整性与分组，通知以完整性判恢复；摘要截断仍禁止推断恢复 |
| P1 | `inspect/workflow` 没有把任务 deadline 传给探针；同次模型回复里的多个工具也能在预算耗尽后继续执行 | 两个工具传递 deadline；loop 在每次工具调用前检查，未启动的调用写明“未执行”并停止后续调用 |
| P2 | 超长 `inspect` 直接按字符截断，后面的异常可能消失 | 预览保留整个异常清单，完整报告仍落盘 |
| P2 | 排期推进写盘失败被当作“没任务”；坏排期被暂停但 `--once` 仍成功 | `_claim_due/run_due` 为真实失败落可查询的 failed 记录，失败退出码为 1；暂停、删除后的正常跳过不算失败 |
| P2 | 最近成功时间未持久保存，后续失败后无法查询 `last_success` | `_update_entry_state` 成功时更新，失败保留上次成功时间 |
| P2 | 磁盘路径接受 DEL，违反拒绝控制字符的配置约束 | 路径验证同时拒绝 `0x7f` |

调用方、工具 schemas 和 workflow 格式保持兼容；原来只期望返回正常任务的两条坏排期测试，
同步验证新增失败记录和失败退出码。

## 3. 通知与事件

| 级别 | 可复现问题与影响 | 修复位置及结果 |
| --- | --- | --- |
| P1 | 成功巡检结果落盘后、发送前进程退出，异常不会补发；配置错误修复后也没有可重试发件箱 | 调度补处理所有未通知终态，按时间先后处理；无发件箱的处理错误保留 60 秒退避重试 |
| P1 | 积压通知分批补发，或配置修复后补旧记录，能在新健康/新异常之后反向覆盖状态；不同任务检查同一目标也会发生 | `notify` 保存任务及目标/分组的观测时间，健康采样也记时间；旧观测不能新增或恢复较新的异常，一次性 missed 事件保留 |
| P1 | 首次告警发送失败却被视为用户已收到，随后会推送无来由的恢复 | 区分发送尝试时间与真正送达时间；从未送达的异常恢复时静默清除 |
| P1 | 恢复消息重试成功后未清状态，下轮再次发恢复；告警复发后还可能补发旧恢复 | 重试成功回写送达及恢复状态；复发取消 pending recovery；通知 id 绑定当前待发状态，旧恢复失效 |
| P1 | 聚合告警中部分项目已恢复或被新级别取代，旧消息只因另一项仍异常就整条补发；missed 又会因不是 open 状态而被丢弃 | 重试按项目重建有效载荷；保留全部结构化项目供重建，正文仍有限长；一次性事件可重试 |
| P1 | 降级被抖动窗口压制后更新了观测级别，稳定降级不再通知；首次发送失败时也可能把所有告警一起压掉 | 级别变化比较最后尝试通知的级别；未真正送达时不应用降级抖动抑制 |
| P1 | webhook 错误体或异常回显 URL/path/token；结构化 payload、发件箱和状态元数据可能保留普通秘密 | 错误记录移除已知渠道凭据，再统一脱敏、截断；发送和持久化出口均递归脱敏 |
| P2 | 重试遇到静默后没有重新武装提醒；去重时不更新 last_seen；停用渠道后恢复态会悬挂 | 静默标记 needs_notify，解除后可重新提醒；去重仍刷新观测；无受众时清除恢复态 |
| P2 | 发件箱合法 JSON 中出现错误 attempts、列表类型 severity/fingerprint、损坏报告路径，会使整批查询或重试异常 | 读取时校验状态机实际使用的字段形状，跳过坏记录；损坏去重状态按不可信处理 |
| P2 | 事件文件只剩轮转后的 `.1` 时，`events tail` 返回空 | 查询不再以当前文件存在为前提，轮转历史仍可读取 |
