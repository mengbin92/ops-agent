## 3. 必须修复：远程恢复的实际目标与权限

| 问题 | 具体触发与影响 | 最小修复 |
| --- | --- | --- |
| P1：快照与下发可落到不同主机 | 多次 `_ssh` 重新读取 targets；采集后换 host，后续命令可能使用旧授权发到新主机 | 操作内固定目标配置；回滚拿锁后再校验快照环境及机器身份 |
| P1：机器指纹探测失败仍通过 | 有 recorded machine，但当前 SSH 失败或输出不可用时静默跳过；登录输出也可能污染指纹 | 显式标记解析，已有机器身份而无法重新确认时拒绝恢复 |
| P1：软链接权限被恢复成 0777 | cat 跟随链接，stat 却记录链接本身权限，恢复后放宽真实配置权限 | GNU/BSD stat 跟随真实文件；八进制稳健解析；合法 0000 不得默认成 0600 |
| P1：原子替换改变现有文件属主 | mktemp 属于 SSH 用户，rename 后服务用户的 0600 文件不可读 | 对已有文件，rename 前保留当前数值 uid/gid；保留失败则原文件不动。新建文件仍明确报告需人工核对属主 |
| P1：软链接改向会覆盖另一文件 | 快照时指向 A，之后文件链接或父目录链接指向 B，原恢复会把 A 的旧内容写到 B | 新快照和回滚前副本记录物理路径；预检与实际恢复脚本都比较路径，改向就拒绝；旧快照提示缺少绑定 |
| P1：断线或缺后验被记为明确失败/成功 | 恢复 SSH 255、信号退出可能已经完成 rename；mode 缺失、不匹配或后验字节异常也可能被误报 | 断线、信号、缺后验和不一致后验记 unknown；had/size/mode 必须可解析；成功终态在目标锁内落盘 |
| P2：过深软链接或非普通文件继续恢复 | 链接超过解析上限后仍可能替换链接；目录等目标也可进入写入流程 | 超过 8 层或非普通文件明确拒绝；路径父目录不存在不回落到根目录 |
| P2：本地旧快照权限处理不一致 | 合法 mode=0 被 `or 0600` 改写；旧快照没 mode 时把已有可执行文件统一降权 | 区分 0 与 None；旧快照覆盖时保留当前权限，重建用 0600 |
